## Directory Purposes

**`Code/Server/`:**
- Purpose: Everything that runs on the Raspberry Pi mounted in the hexapod — hardware drivers, kinematics/gait engine, and the TCP server + PyQt5 on/off GUI.
- Contains: Flat list of Python modules (no subpackages); one `.py` file per hardware subsystem or concern; two flat-file config artifacts (`point.txt`, `params.json`).
- Key files: `main.py` (entry point), `server.py` (networking + command dispatch), `control.py` (kinematics/gait brain).

**`Code/Client/`:**
- Purpose: Desktop teleoperation console — connects to the Server over TCP, renders the video stream, and exposes movement/LED/camera/calibration/face-ID controls.
- Contains: Flat list of Python modules (mirrors Server's flat-file style); `Face/` and `Picture/` subdirectories hold non-code assets (trained face data, UI images).
- Key files: `Main.py` (entry point/main window), `Client.py` (networking).

**`Code/Libs/`:**
- Purpose: Vendored, independently-installable third-party hardware driver packages that the Server imports (`mpu6050`, `rpi_ws281x`).
- Contains: Full pip-installable package source trees, each with their own `setup.py`, plus generated `build/`, `dist/`, `*.egg-info/` directories from prior local installs (these are build output, not source, but are present in the working tree).
- Key files: `mpu6050/mpu6050/mpu6050.py`, `rpi-ws281x-python/library/rpi_ws281x/`.

**`Application/`:**
- Purpose: Distribution of the compiled/packaged desktop Client app for end users who don't want to run from Python source, with per-OS `Face/`, `Picture/`, `IP.txt`, `point.txt` support files matching `Code/Client/`.
- Contains: Large platform-specific binaries (`mac` ~100MB, `windows.exe` ~73MB) — not source code.
- Generated: Yes (built from `Code/Client/` sources, not maintained by hand in this repo).

**`Datasheet/`, `Picture/` (top-level), `*.pdf`:**
- Purpose: Reference documentation — component datasheets, assembly/usage tutorial, calibration diagram, battery guide, README images.
- Contains: PDFs and images only, no code.

**`.planning/codebase/`:**
- Purpose: Output location for GSD codebase-mapping documents (this file and its siblings).

## Key File Locations

**Entry Points:**
- `Code/Server/main.py`: Server process entry point (Raspberry Pi side).
- `Code/Client/Main.py`: Client process entry point (PC side).
- `Code/Server/myCode.py`, `Code/Server/test.py`: Standalone non-networked scripts for hardware bring-up/demo.

**Configuration:**
- `Code/Server/params.json`: PCB version / Raspberry Pi version flags (read/written by `Code/Server/parameter.py`).
- `Code/Server/point.txt` / `Code/Client/point.txt`: Per-leg calibration coordinates (tab-separated integers, one row per leg).
- `Code/Client/IP.txt`: Last-used server IP address, loaded into the connect field on Client startup.

**Core Logic:**
- `Code/Server/control.py`: Inverse kinematics, gait generation, posture balance, calibration state.
- `Code/Server/server.py`: Command protocol dispatch and video/command socket handling.
- `Code/Client/Client.py`: Client-side socket handling and video decode.

**Testing:**
- No dedicated test directory or test framework configuration exists for `Code/Server/` or `Code/Client/`. `Code/Server/test.py` is an interactive manual hardware smoke test (not an automated test suite).
- `Code/Libs/rpi-ws281x-python/library/tests/`: Test files belonging to the vendored `rpi_ws281x` package only (unrelated to Server/Client application logic).

## Naming Conventions

**Files:**
- `Code/Server/`: lowercase, `snake_case.py` (e.g. `pca9685.py`, `ultrasonic.py`, `spi_ledpixel.py`), one file per subsystem.
- `Code/Client/`: mixed case — some files `PascalCase.py` for GUI/domain classes (`Client.py`, `Command.py`, `Calibration.py`, `Face.py`, `Thread.py`, `PID.py`, `Main.py`), others lowercase for Qt Designer-generated UI modules (`ui_client.py`, `ui_led.py`, `ui_face.py`). New Client modules should follow whichever pattern matches their role: `PascalCase.py` for a new class-based module, `ui_*.py` only for Qt Designer output.
- Config/data files use lowercase with extension indicating format: `point.txt`, `params.json`, `IP.txt` (capitalized on Client side only, matches existing file).

**Directories:**
- Top-level: `PascalCase` (`Code`, `Application`, `Datasheet`, `Picture`).
- Under `Code/`: `PascalCase` for the two main programs (`Server`, `Client`, `Libs`); vendored library directories keep their upstream naming (`mpu6050`, `rpi-ws281x-python`).

**Classes:**
- `PascalCase` matching the file's primary responsibility, usually one dominant class per file (`Server`, `Control`, `Servo`, `PCA9685`, `Led`, `IMU`, `ADC`, `Ultrasonic`, `Buzzer`, `Camera`, `Client`, `Face`).
- Constants collected in an all-caps-named class acting as a namespace: `COMMAND` (`Code/Server/command.py`, `Code/Client/Command.py`), with attributes like `CMD_MOVE`, `CMD_LED`.

**Methods/functions:**
- `snake_case` throughout Server code (`set_servo_angle`, `read_battery_voltage`, `calculate_posture_balance`), consistent across both processes.

## Where to Add New Code

**New robot behavior / gait / posture command:**
- Protocol constant: add to both `Code/Server/command.py` and `Code/Client/Command.py` (must be kept identical — see ARCHITECTURE.md anti-patterns).
- Server-side handling: add an `elif cmd.CMD_YOUR_CMD in command_parts:` branch in `Server.receive_commands()` (`Code/Server/server.py`), or route through `Control.command_queue` and handle it inside `Control.condition_monitor()` (`Code/Server/control.py`) if it needs the continuous polling loop.
- Client-side trigger: wire a new GUI control in `Code/Client/ui_client.py` (Qt Designer layout) and a corresponding slot in `Code/Client/Main.py` that calls `self.client.send_data(...)`.

**New hardware peripheral driver (Server):**
- Add a new `snake_case.py` module in `Code/Server/` mirroring the existing pattern: constructor opens the hardware resource, public methods are imperative verbs, include an `if __name__ == '__main__':` self-test block.
- Instantiate the new controller once inside `Server.__init__` (`Code/Server/server.py`) alongside `led_controller`, `adc_sensor`, etc.

**New GUI window (Client):**
- Design the layout as a Qt Designer-generated `ui_<name>.py` module (matching `ui_led.py`/`ui_face.py` pattern), then create a `PascalCase.py` window class that mixes in the `Ui_*` class the way `Calibration.py` does, and open it from `Code/Client/Main.py`.

**Shared/duplicated logic (PID, Thread utilities, command constants):**
- These currently exist as manually-synced duplicate files in `Code/Server/` and `Code/Client/`. When modifying `pid.py`/`PID.py`, `Thread.py`/`Thread.py`, or `command.py`/`Command.py`, update both copies in the same change.

**Vendored driver updates:**
- Changes to IMU or LED strip low-level drivers belong in `Code/Libs/mpu6050/mpu6050/` or `Code/Libs/rpi-ws281x-python/library/rpi_ws281x/` respectively, followed by reinstalling the package (`pip install .` from that directory) so `Code/Server/imu.py`/`rpi_ledpixel.py` pick up the change.

## Special Directories

**`Code/Server/__pycache__/`, `Code/Client/__pycache__/`:**
- Purpose: CPython bytecode cache.
- Generated: Yes.
- Committed: No (present in working tree per `git status` as untracked; should stay untracked).

**`Code/Libs/mpu6050/build/`, `Code/Libs/mpu6050/dist/`, `Code/Libs/mpu6050/*.egg-info/`:**
- Purpose: Artifacts from a local `pip install`/`setup.py build` of the vendored `mpu6050` package.
- Generated: Yes.
- Committed: Present in the working tree; treat as build output, not source, when navigating.

**`Code/Libs/rpi-ws281x-python/library/build/`, `.../dist/`, `.../*.egg-info/`:**
- Purpose: Same as above, for the vendored `rpi_ws281x` C-extension package (includes compiled `.so` artifacts under `build/lib.linux-aarch64-cpython-313/`).
- Generated: Yes.
- Committed: Present in the working tree; treat as build output, not source.

**`Application/mac/`, `Application/windows/`:**
- Purpose: Pre-built, packaged Client desktop binaries for distribution to end users.
- Generated: Yes (built from `Code/Client/`, not hand-maintained).
- Committed: Yes (large binaries checked into the repo).
