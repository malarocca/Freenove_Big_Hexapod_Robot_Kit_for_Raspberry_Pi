# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This project is a PyQt5 desktop teleoperation client (`Code/Client/`), not a web app. The shadcn/web design-contract template below has been adapted to this project's actual UI stack: a single fixed-pixel, Qt Designer-generated screen (`Code/Client/ui_client.py`, imported as a mixin into `Code/Client/Main.py`) with an established dark QSS theme. Per CLAUDE.md, `ui_client.py` is generated code and must not be hand-edited directly — new widgets are added either by regenerating through Qt Designer + `pyuic5`, or by extending `Ui_client.setupUi()` following its existing per-widget pattern (`QtWidgets.Widget(client)` → `setGeometry` → `setFont` → `setStyleSheet` → `setText`), consistent with every other widget already in that file.

Phase 1's entire UI surface is two new widgets: an Auto Mode toggle button (AUTO-01) and an always-visible status badge (AUTO-04). No other screens, views, or data surfaces are added this phase.

This screen is an absolute-pixel `setGeometry(x, y, w, h)` layout, not a flexbox/grid token system — there is no existing 8-point spacing scale to confirm. The values below are the placement contract for this phase's two new widgets, chosen to match the sibling controls already on this exact row/screen rather than inventing a new grid.

| Token | Value | Usage |
|-------|-------|-------|
| Row height | 30px | Height of both new widgets — matches every existing `Button_*` on screen (e.g. `Button_Face_ID`, `Button_Connect`, all `Code/Client/ui_client.py` buttons are 30px tall) |
| Inter-widget gap | 10px | Gap between the toggle button and its adjacent status badge — matches the tightest existing button-to-button gaps on screen (e.g. `Button_IMU`↔`Button_Sonic`) |
| Row-anchor gap | 20px | Gap between `Button_Face_ID` (existing, ends at x=130) and the new toggle button — matches existing inter-control gaps elsewhere on the same row band |

**Concrete placement (exact geometry for the executor):**

| Widget | `setGeometry` | Notes |
|--------|----------------|-------|

## Typography

This screen has no heading hierarchy today — every label and button uses the same 10pt Arial at one weight (regular/400). This phase introduces exactly one new typographic distinction: **bold weight, reserved solely for the status badge**, so it visually stands out as an always-visible indicator rather than reading as just another button label (per CONTEXT.md D-12).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (existing convention — button/label text) | 10pt (~13px) | Regular (400) | 1.0 (fixed single-line widgets, no wrap) |
| Status badge (new — `label_Auto_Status` only) | 10pt (~13px) | Bold (700, `QFont.setBold(True)`) | 1.0 |
| Heading | not applicable | — | — | This is a flat, single-screen control panel with no section headings anywhere |
| Display | not applicable | — | — | Same as above |

Exactly 2 weights declared for this phase: Regular (400, everything else) and Bold (700, badge only). Do not introduce a third weight.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Dynamic toggle-button label on `Button_Auto`, following this codebase's existing dynamic-label toggle convention (`Button_Connect`: "Connect"/"Disconnect"; `Button_Buzzer`: "Buzzer"/"Noise"): **"Start Auto Mode"** when idle → **"Stop Auto Mode"** when active. Button always reflects the action the next click performs, not the current state (verb-first). |
| Status badge (AUTO-04's "visible indicator") | **"AUTO MODE ACTIVE"** (bold, green `#35C759`) while running; **"Auto Mode: Off"** (regular weight, default `#DCDCDC`) while idle. Badge text is always present at both states — never hidden/blank — and updates immediately (no debounce/fade) on: (a) user toggling off, (b) any manual command preempting auto mode (AUTO-02), (c) the bounded-runtime auto-halt (AUTO-03). Binary only — this phase never shows a third string for "avoiding"/"stopped-for-obstacle" sub-states (explicitly deferred to Phase 3 per D-13/AUTO-05). |
| Empty state heading | not applicable — this phase adds a stateless status indicator, not a data view/list |
| Empty state body | not applicable, same reason |
| Error state | If `Button_Auto` is clicked while the client isn't connected to the robot (command can't be sent), show inline text directly below/beside the toggle: **"Not connected — connect to the robot before starting Auto Mode."** Matches how other controls on this screen silently no-op without connection; this phase adds an explicit message rather than a silent failure, since the whole point of the badge is visibility. `label_Auto_Status` stays in its idle "Auto Mode: Off" state in this case — it must never claim "ACTIVE" for a command that didn't reach the robot. |
| Destructive confirmation | None. Turning auto mode off — whether by explicit user toggle, manual-command preemption, or timeout — is never treated as a destructive action requiring a confirmation dialog. This is intentional: D-10 requires manual override to cut in "immediately, no wait," and a confirmation dialog would directly violate that safety requirement. No confirmation dialogs exist anywhere in this phase's UI surface. |

## Interaction Contract (phase-specific supplement)

Beyond the template's standard sections, this phase's UI correctness hinges on wiring behavior, not just visual styling — captured here for the planner/executor since it's load-bearing for AUTO-01/02/04:

1. **Binary state only (D-13).** `label_Auto_Status` has exactly two visual states (Active/Idle per the Color and Copywriting tables above). Do not add a third sub-state (walking/avoiding/stopped) this phase — that's explicitly Phase 3 scope (AUTO-05, CONFIG-02).
2. **Badge is independent of button-press visual state (D-12).** The badge must be a separate, always-visible `QLabel`, not merely the toggle button's own `:pressed`/`:checked` QSS styling and not a transient toast/notification. It reflects server-confirmed auto-mode state, not just "the button was clicked."
3. **Immediate update on three distinct triggers:** explicit user toggle-off, manual command preempting auto mode (AUTO-02), and bounded-runtime auto-halt (AUTO-03) must all flip the badge from Active→Idle with no perceptible delay, consistent with how the rest of this phase's safety behavior is specified (D-09/D-10) — this is a client-side rendering concern only; the underlying arbitration/timer logic is server-side and out of this UI spec's scope.
4. **Placement and generated-file discipline.** New widgets go into `Ui_client.setupUi()` in `Code/Client/ui_client.py` following the file's existing generation pattern exactly (matching surrounding widgets' construction order: instantiate → `setGeometry` → `setFont` → `setStyleSheet` → `setText` → `setObjectName`), and wiring (`clicked.connect(...)`, state-driven `setText`/`setStyleSheet` updates) goes in `Code/Client/Main.py`, matching where `Button_Connect`/`Button_Buzzer`'s equivalent logic already lives (`Main.py:33,42-43,526-620` per this session's `grep`).
