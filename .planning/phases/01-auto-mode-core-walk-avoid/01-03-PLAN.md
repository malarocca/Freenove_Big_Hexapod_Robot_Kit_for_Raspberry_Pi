## Phase Goal

**As a** hexapod operator, **I want to** watch the robot look around when something blocks it and steer itself toward open space instead of just stopping dead, **so that** it can keep patrolling a room on its own without me rescuing it every time it meets a chair leg.

<objective>
Turn plan 01's blunt "stop when something is ahead" into the real reactive avoidance behaviour the phase promises: stop, sweep the head across three bearings, pick the more-open side, turn about 45 degrees toward it, re-centre the head, and resume — with a hysteresis gap between the stop threshold and the resume threshold so the robot does not oscillate.

This is the last slice of Phase 1's core value. It touches only the `Code/Server/autonomy/` package; the protocol, the client UI, the arbitration gate, the bounded-runtime timer and the manual-override path are all already proven by plans 01 and 02 and are not modified here.

Purpose: SENSE-02 and AVOID-01 are the difference between a robot that stalls in front of a sofa and one that gets around it.
Output: a three-bearing sweep in `perception.py`, a CLEAR/CAUTION/BLOCKED hysteresis state machine plus turn sequencer in `behavior.py`, and their tunables in `settings.py`.

Deliberately NOT in this plan (Phase 2 scope, do not pull forward): varied or clearance-scaled turn angles (AVOID-02), consecutive-avoidance "stuck" escalation (AVOID-03), proximity-proportional slowdown (AVOID-04), and wall-follow patrol (PATROL-01). D-07 fixes this phase's turn at a constant ~45 degrees on purpose.
</objective>

  <action>
    All edits are in `Code/Server/autonomy/behavior.py`. Do not touch `server.py`, `control.py`, or the client — the arbitration gate, the manual-override abort, the bounded-runtime timer and the `CMD_AUTO` protocol are already correct and proven.

    1. Widen `decide` into the three-state hysteresis machine AVOID-01 requires. Change the pure function to `decide(distance_cm, previous_state)` returning one of the string constants `BLOCKED`, `CAUTION`, `CLEAR` defined as module-level names. Rules, in this order:
       - `distance_cm is None` -> `BLOCKED`. Unknown is never clear; this is SENSE-01 and it must be the first branch so it cannot be shadowed by a numeric comparison.
       - `distance_cm < settings.STOP_THRESHOLD_CM` (20.0) -> `BLOCKED`. This is CAUTION-01's "stop and reassess"; there is no nudge-past branch and none may be added.
       - `distance_cm > settings.RESUME_THRESHOLD_CM` (35.0) -> `CLEAR`.
       - otherwise (20.0 <= distance <= 35.0, the hysteresis band) -> `CAUTION`, which means "hold whatever we were doing": if `previous_state` was `CLEAR` keep returning `CLEAR`, if it was `BLOCKED` or `CAUTION` keep returning `BLOCKED`. Implement that latch explicitly rather than returning a bare `CAUTION` the caller has to interpret, so the pure function is fully testable. Keep `CAUTION` as an observable return only if you also make the caller's handling of it identical to the latched value; the simpler and preferred shape is to return the latched `CLEAR`/`BLOCKED` and expose the band membership through a second return value or a separate `in_hysteresis_band(distance_cm)` helper used only for logging.
       The whole point of the band (D-06) is that the stop trigger sits at 20 cm but forward motion only resumes once the heading reads past 35 cm, so an obstacle parked at 27 cm produces one stable decision instead of a stop/go oscillation.

    2. Rework the decision loop's blocked path in `_run` into a `_handle_blocked()` sequence. When the state becomes `BLOCKED`:
       a. Emit the HALT/settle intent first, so the robot is standing still before the head moves. Sweeping while walking would attribute bearings to positions the robot has already left.
       b. Call `sensor_hub.sweep_bearings()`. Log the full returned table via `print` — this is the operator's only window into why the robot chose what it chose, and it feeds Phase 4's CONFIG-03 logging.
       c. Choose a heading from the table. Treat any bearing whose value is `None` as UNAVAILABLE and exclude it from selection entirely; never rank an unknown bearing above a measured one and never fall back to "well, nothing measured, so go straight". Compare only the `left` and `right` bearings for the turn direction; require the winner to read strictly greater than `settings.RESUME_THRESHOLD_CM` to be considered open at all. If neither side qualifies — both blocked, both unknown, or both inside the resume threshold — do not turn toward either. Instead perform the same fixed turn toward `left` as an arbitrary but deterministic default, log that no side was open, and let the next loop iteration re-evaluate; the robot keeps rotating in place rather than driving into anything, which is the safe failure mode. Do not add randomisation or escalation here — varied turns (AVOID-02) and stuck detection (AVOID-03) are Phase 2 and pulling them forward would pre-empt that phase's design.
       d. Execute the turn: emit the in-place rotation intent `['CMD_MOVE', settings.WALK_GAIT, '0', '0', str(settings.WALK_SPEED), str(sign * settings.TURN_STEP_DEG)]` once per cycle, `settings.TURN_STEPS` times, with a short wait between emissions. Two things make this non-obvious and both must be handled: `condition_monitor` resets `command_queue` to the empty six-element list after each x==0/y==0 gait cycle, so each of the five rotations needs its own emission; and `run_gait` applies the entire `angle` value as body yaw across one cycle, so five cycles at 9 degrees gives the ~45 degrees D-07 specifies. Between emissions, wait for `command_queue[0]` to go back to `''` (bounded by a timeout of roughly two gait cycles) rather than sleeping a fixed guess, so the turn tracks real gait completion. Check `self.auto_mode_active.is_set()` before every single emission and abandon the turn immediately if it is clear — a human pressing an arrow key mid-turn must not have to wait out four more rotations (D-10). All six intent fields must be strings.
       e. After the turn, emit the HALT/settle intent once, then let the main loop re-evaluate from `sensor_hub.latest()` on its next tick. Do not resume forward walking from inside `_handle_blocked`; resumption must go through `decide` so the 35 cm hysteresis gate actually governs it.

    3. Keep every safety property plan 01 established, and verify each is still true after the rewrite: the whole `_run` body stays inside `try / except Exception as e: print(...)` with a fail-safe stop; the bounded-runtime deadline check stays the first statement in the try body so a long sweep or turn can never outlive the 300 s budget; `_emit` still re-checks the gate immediately before writing; autonomy still never sets `control_system.manual_preempt`; and `Thread.stop_thread` is still never imported. Add an explicit deadline check between `_handle_blocked`'s steps as well — a sweep plus five turn cycles is on the order of three seconds, long enough to matter at the boundary.

    4. Extend the `if __name__ == '__main__':` self-test with assertions for the new state machine, keeping the existing four cases and adding: `None` is BLOCKED regardless of previous state; `19.9` is BLOCKED; `36.0` is CLEAR; `27.0` with previous CLEAR stays CLEAR; `27.0` with previous BLOCKED stays BLOCKED; `35.0` exactly (boundary) with previous BLOCKED stays BLOCKED; `20.0` exactly with previous CLEAR does not return CLEAR. Also assert the heading chooser: a table with `left=None, right=60.0` picks right; `left=60.0, right=None` picks left; `left=None, right=None` picks the deterministic default and reports no side open; `left=25.0, right=30.0` (both inside the resume threshold) reports no side open. This block must stay hardware-free so it runs anywhere — it is this phase's only repeatable automated check.
